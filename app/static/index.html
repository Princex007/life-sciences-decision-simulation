Time Series Forecasting

Extrapolate an observed time series using a deterministic trend fitted to its historical values. Import a CSV or Excel file, or paste the numbers, and project that history forward. It is its own option, separate from a simulation, and uses the same deterministic straight-line fit as the Trend projection forecast model, so a number produced here matches the same number produced inside a run.

This draws a line through the numbers you give it. That is an extrapolation of the recent trend, not a causal forecast, and it has no confidence interval. The fit error is reported so you can judge how straight the line really is.

Analogue-Based Forecasting

    
Estimate a target product's trajectory by scaling the observed trajectory of a comparable reference product to a target peak you specify. The reference series is a DIFFERENT product's recorded history; its shape is multiplied by one factor so its own highest reading lands on the peak you enter, then that rescaled shape is fitted and projected. No simulation is run — this is the same arithmetic the Reference product analogue forecast model uses inside a run.

    
One multiplier preserves the borrowed series' relative growth and converts nothing else: the peak you enter must be stated in the same metric and unit as the series you are borrowing, because a factor cannot turn patients into share. The projection is only as good as the claim that these two products launch alike.

Driver-Based Forecasting

    
Project outcomes using external driver trajectories, baseline variables, and declared driver-to-variable effects. List several external drivers, give each an index trajectory and one pathway onto a named model variable, and give each affected variable its baseline value and growth rate. Read where the combined drift and pathways take every variable across the forecast horizon. No simulation is run, and it uses the same index continuation, level scaling and transition semantics the Exogenous driver projection model applies past a run's horizon.

    
Inside a run a pathway fires only in the periods its trajectory covers and agents keep reacting to the result. Here every pathway fires in every projected period at that period's projected index, and nothing endogenous responds. What is projected is the external environment plus the growth rates you declare.

1. Simulation
The objective scorer selects decisive choices. The LLM is called only when scores are tied or unavailable.
Both limits apply only to the LLM policy and span every branch of one run. When a limit is reached the remaining decisions are made by the configured rule-based policy, and the run reports that no model chose them. A model selecting an action is never evidence that the action is correct.

      
2. World
Variables are stored as JSON values. Descriptions and evidence grades travel with the definition as documentation.

3. Agents
Edit stakeholder names, objectives, decision timing, actions, and observations with forms. You only need the advanced JSON editor for custom agent settings.
Advanced agent settings (JSON)

      
4. Actions
Actions define the choices agents can make and which state variables they affect. Add simple actions from each agent card in step 3; constraints and generated events stay editable in the JSON below.
Advanced action definitions (JSON)

      
5. Triggers
Triggers determine when each agent gets to make a decision. Set them per agent in step 3 (“Once at start” or “Every round”); state-condition triggers stay in the JSON below.
Advanced trigger definitions (JSON)

      
6. External environment

        
Drivers are outside forces — technology, regulation, pricing pressure — that change the world on a schedule. They are compiled into ordinary scheduled events and transition rules, so the same deterministic engine applies them.

        
Driver strengths below are configured assumptions, not measurements. Variants let you compare worlds; they do not make any variant more true.
